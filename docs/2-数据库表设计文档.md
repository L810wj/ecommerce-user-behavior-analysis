# 数据库表设计文档

## 1. 项目数仓整体设计思路

本项目围绕电商用户行为日志建设一个离线数仓。原始数据来自 `data/raw/user_behavior_raw.csv`，包含用户浏览、加购、收藏、购买等行为。数仓采用 ODS、DWD、DWS、ADS 四层结构，将原始日志逐步加工为可分析、可汇总、可面试讲解的业务指标。

设计目标：

- ODS:  保留原始数据，便于追溯问题；
- DWD:  清洗明细数据，统一字段口径；
- DWS:  按用户、商品、类目等常用粒度沉淀汇总表；
- ADS:  输出核心业务指标、转化漏斗、留存、RFM 和热门排行。

## 2. 数仓分层含义

### ODS 层

ODS 是原始数据层，表名为 `ods_user_behavior_raw`。这一层尽量保留原始 CSV 字段，不做复杂加工，主要用于数据落库、备份和问题追溯。

### DWD 层

DWD 是明细数据层，表名为 `dwd_user_behavior_detail`。这一层对 ODS 数据做标准化清洗，包括过滤非法行为、转换时间字段、生成日期字段和行为标记字段。DWD 层是一切后续聚合分析的基础。

### DWS 层

DWS 是汇总数据层，按业务常用分析粒度聚合数据。本项目设计了用户每日、商品每日、类目每日三张汇总表，便于计算活跃、转化、热度和留存等指标。

### ADS 层

ADS 是应用数据层，面向最终业务分析和看板展示。本项目输出每日核心指标、转化漏斗、留存、RFM 用户分层、热门商品、热门类目和小时趋势。

## 3. 每一层为什么这样设计

ODS 层保留原始数据，是为了避免清洗逻辑出错后无法回溯。DWD 层统一明细口径，是为了让后续 SQL 不重复处理脏数据。DWS 层沉淀高频分析粒度，是为了提升复用性和查询效率。ADS 层直接服务业务问题，是为了让指标结果更容易被分析、看板和面试讲解使用。

## 4. 表设计说明

| 层级 | 表名 | 业务粒度 | 主要用途 |
| --- | --- | --- | --- |
| ODS | ods_user_behavior_raw | 原始行为日志，一行一次行为 | 保留原始 CSV 数据，支持追溯 |
| DWD | dwd_user_behavior_detail | 标准化行为明细，一行一次行为 | 清洗后明细层，支持所有后续聚合 |
| DWS | dws_user_daily_behavior | 用户 + 日期 | 分析用户活跃、购买、留存和 RFM |
| DWS | dws_item_daily_behavior | 商品 + 日期 | 分析商品热度和商品转化 |
| DWS | dws_category_daily_behavior | 类目 + 日期 | 分析类目热度和类目转化 |
| ADS | ads_daily_core_metrics | 日期 | 每日 PV、UV、DAU、购买和转化 |
| ADS | ads_conversion_funnel | 行为阶段 | 分析 pv、cart、fav、buy 漏斗 |
| ADS | ads_user_retention | 基准日期 + 留存天数 | 分析活跃用户次日、3 日、7 日留存 |
| ADS | ads_rfm_user_value | 用户 | 用户价值分层 |
| ADS | ads_top_items | 商品排行 | 热门商品 Top 20 |
| ADS | ads_top_categories | 类目排行 | 热门类目 Top 20 |
| ADS | ads_hourly_behavior_trend | 小时 | 分析全天活跃节奏 |

## 5. 核心字段说明

ODS 和 DWD 共同核心字段：

- `user_id`：用户 ID；
- `item_id`：商品 ID；
- `category_id`：类目 ID；
- `behavior_type`：行为类型，包含 `pv`、`cart`、`fav`、`buy`；
- `behavior_time`：行为发生时间；
- `behavior_date`：标准行为日期；
- `hour`：行为发生小时；
- `weekday`：星期几，0 表示周一，6 表示周日；
- `is_pv`、`is_cart`、`is_fav`、`is_buy`：行为标记字段。

DWS 和 ADS 常用指标字段：

- `pv_count`：浏览次数；
- `cart_count`：加购次数；
- `fav_count`：收藏次数；
- `buy_count`：购买次数；
- `uv_count`：访问用户数；
- `buyer_count`：购买用户数；
- `click_to_buy_rate`：点击到购买转化率；
- `rank_no`：排名。

## 6. 核心指标口径说明

### PV

PV 指浏览次数，口径为 `behavior_type = 'pv'` 的行为记录数。

### UV

UV 指访问用户数，口径为有过行为或浏览行为的去重 `user_id` 数。本项目每日核心指标中使用当日有行为的去重用户数。

### DAU

DAU 指日活跃用户数，口径为某日有任意行为的去重用户数。由于当前模拟数据没有登录事件，因此用行为活跃近似 DAU。

### 购买用户数

购买用户数指发生过 `buy` 行为的去重用户数。

### 点击到购买转化率

点击到购买转化率用于商品或类目分析，口径为 `buy_count / pv_count`。当 `pv_count = 0` 时，转化率记为 0，避免除零错误。

### 加购到购买转化率

加购到购买转化率可在 ADS 或后续分析中用 `buy_users / cart_users` 或 `buy_count / cart_count` 表示。面试时需要说明本项目更推荐用户数口径，因为它更接近真实转化链路。

### 留存率

当前模拟数据没有注册时间，因此留存定义为“某日活跃用户在第 N 天是否仍然活跃”。口径为 `retained_users / new_or_active_users`，其中 `new_or_active_users` 实际表示基准日活跃用户数。

### RFM

RFM 用于用户价值分层：

- R：Recency，最近一次购买距观察截止日的天数；
- F：Frequency，购买频次；
- M：Monetary，消费金额或价值。

当前数据没有金额字段，因此 `monetary` 暂用购买次数近似。后续如果引入订单金额，可以替换为真实 GMV 或支付金额。

Recency 的口径是“最近一次购买日期距观察截止日的天数”，观察截止日取数据中的最大 `behavior_date`。如果用户没有任何购买行为，则没有最近购买日期，本项目在 ADS 层将 `recency_days` 设置为 `999`，并将这类用户归为“未购买用户”。这样可以避免把最近一次浏览、加购或收藏误当成最近购买，从而保证 RFM 口径和业务含义一致。

### 热门商品

热门商品按商品维度汇总，优先按 `pv_count` 排名，同时保留加购、收藏、购买、购买用户数和点击到购买转化率。

### 热门类目

热门类目按类目维度汇总，优先按 `pv_count` 排名，用于判断流量集中在哪些类目，以及类目转化是否健康。

## 7. 面试时如何讲这个数仓设计

可以按以下顺序讲：

1. 先说明项目场景：这是一个电商用户行为分析项目，原始日志包含浏览、加购、收藏和购买行为。
2. 再说明为什么分层：ODS 保留原始数据，DWD 做标准化清洗，DWS 按业务粒度汇总，ADS 输出可直接分析的指标。
3. 讲清楚核心链路：`ods_user_behavior_raw` 到 `dwd_user_behavior_detail`，再到用户、商品、类目三类 DWS 汇总表，最后形成 ADS 指标表。
4. 重点解释指标口径：PV、UV、DAU、购买用户数、点击到购买转化率、留存和 RFM。
5. 最后说明项目价值：这个设计既能支持数据分析岗位讲指标，也能支持数据开发岗位讲数仓分层和 ETL，还能为后续机器学习岗位的购买预测特征工程打基础。
